# Examination — Generate Admit Card

Status: **FINAL**
Reference: `generate-admit-card.html`

Every student with a configured exam structure — preview and print. No configuration lives here; it all comes from Admit Card Structure.

---

## Frontend

**Toolbar**: row1 (checkbox-selection-driven "Print Selected (N)" button, disabled until rows checked) + row2 (Class/Stream/Exam filters).

**Table**: checkbox, Student, Roll No., Class, Stream, Exam Name, Preview (eye icon → single-card preview modal, `window.print()` for that one).

**Print Selected**: opens a print-mode choice modal (not a settings form) — "One Student in One Page" vs "Two Students in One Page" as two clickable illustrated options, then generates the combined print-preview and calls `window.print()`. This print-mode-choice pattern (illustrated option cards, not a dropdown) is the same shape Generate Marksheet and Generate TC use for their own print/bulk options — reuse it.

**Print layout**: `@media print` rules hide chrome and force `page-break-after:always` per card — the `.letter-frame` card design matches the Admission Letter's shared letterhead language (school logo/name/affiliation header).

## Backend

No configuration model — reads `AdmitCard` documents generated by Admit Card Structure's create/update. `GET` endpoint here is read-only, scoped by the filters shown, `.lean()`+`.select()`'d to what the print template renders.

**Reconciling with `additional-technical-considerations.md`'s "bulk PDF generation is queued" rule**: a single-digit "Print Selected" (a handful of rows a teacher checked by hand) can stay client-side `window.print()` of a rendered preview — no server PDF step needed there. But **"Print Selected" scoped to a whole class/section (dozens to hundreds of cards) goes through the same BullMQ PDF-generation queue as Generate Marksheet/Generate TC's bulk paths** — rendering hundreds of print-ready cards in one browser tab is a real memory/reliability risk at scale, not just a style choice. Treat "how many rows are selected" as the decision point, not a blanket rule either way.
