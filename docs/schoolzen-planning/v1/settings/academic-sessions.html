Reference file - this is the exact, approved render. Match it pixel-for-pixel. Settings → Academic Sessions. Manages the sessions every other page's header session-selector reads from. Exactly ONE session is Active per school at a time — the header selector lets anyone VIEW any past session's data read-only, but new records (admissions, attendance, fees, payroll) are always created against the Active session regardless of which one is being viewed. Creating a session never auto-copies student placements (that's Class Promotion's job) but DOES offer to copy forward config that would otherwise need re-entering every year (Fee Structure, Marksheet Structure, Salary Groups, Holiday Templates).

Create Academic Session

This creates the session as Upcoming — it won't become the active session (and no new records will be saved to it) until you explicitly set it active, typically once the current session ends.

Copy forward from 2026-27 (optional)

Copies the CONFIGURATION only, as a starting point you can edit — never student placements or financial records. Class Promotion is still a separate, explicit step for moving students into this session.

Set 2027-28 as Active
This changes where every new record in the app is saved — every admission, attendance punch, fee payment, and payroll run from this point on goes into 2027-28 instead of 2026-27, for every user at this school, immediately. 2026-27 becomes Closed and stays fully browsable read-only.
